# MLLB-Human: Annotation Guidelines (v1)

Goal: a human-written, human-annotated test set of longitudinal personal documents in which
stances on topics change (or stay stable) over time, with gold labels for every statement,
every stance transition and a set of natural questions. It complements MLLB-Synth, whose
template-generated text cannot show that the system works on real writing.

## 1. Sourcing the documents (choose one per persona, record it in `personas.csv`)
A. **Donated real archives.** Volunteers contribute their own dated notes, journals, emails to
   self, blog drafts or CV versions spanning >= 3 years. Requires informed written consent,
   removal of third-party personal data, and approval by your institution's ethics board/IRB.
B. **Authored personas.** Writers (not the system developers) write 15-40 dated entries for a
   fictional person over 4-8 years, in their own words, following a one-paragraph brief
   ("a nurse who gradually loses faith in remote work, then partly returns to it"). Briefs are
   drawn from `templates/briefs_example.csv`; writers must not see the extraction lexicons.
Do not use LLM-generated text. Ask writers to confirm this in the sign-off sheet.

Target size: >= 30 personas, >= 600 documents, >= 300 questions; at least 25% of personas with
no stance change on their main topic (controls), and topics spread across tech, work, health,
hobbies, relationships, politics-free civic topics.

## 2. Files (see `templates/`)
| file | one row per | key fields |
|---|---|---|
| `documents.csv` | document | persona_id, doc_id, date (YYYY-MM-DD; use the 1st of month if only month known), text |
| `statements.csv` | sentence (auto-generated by `segment.py`) | doc_id, sent_idx, sentence, annotator_id, memory_type, polarity, topic |
| `transitions.csv` | stance change | persona_id, topic, from_doc_id, to_doc_id, change_type, annotator_id |
| `queries.csv` | question | persona_id, query_id, query, query_style, topic, gold_answer |

## 3. Statement labels (`statements.csv`)
- **memory_type**: one of belief, goal, decision, preference, plan, reflection, observation,
  knowledge, event (definitions in Appendix A). Pick the dominant one.
- **polarity**: the author's attitude to the sentence's main subject: -2 strong rejection,
  -1 mild negative, 0 neutral/factual, +1 mild positive, +2 strong adoption/enthusiasm.
  Label what is *written*, not what you infer about the person. Sarcasm: label the intended stance.
- **topic**: the persona's topic label if the sentence is about it (use the exact string from
  `personas.csv`), otherwise a short free label or empty.

## 4. Transitions (`transitions.csv`)
Mark a transition when the author's stance on a topic differs between two documents:
- `reversal`: polarity changes sign (e.g. -1 -> +2);
- `gradual_evolution`: same sign, clearly different position or emphasis;
- `abandonment`: a stated goal/plan is explicitly dropped.
`from_doc_id` is the last document with the old stance, `to_doc_id` the first with the new one.
Do not mark transitions on topics mentioned only once.

## 5. Questions (`queries.csv`)
For each persona write 6-12 questions in four styles: `evolution` ("How has my view on X changed?"),
`plain` ("What do I think about X?"), `when_changed` ("When did I stop wanting X?"),
`point_in_time` ("What did I think about X in 2021?"). Give a short gold answer in your own words
and include at least one question whose answer is not in the documents (gold: "not documented").

## 6. Process and quality control
1. Two annotators label every persona independently (never the developers of the system).
2. Run `python agreement.py annotations/` and report: Cohen's kappa (memory_type), weighted
   kappa and Krippendorff's alpha (polarity), transition F1 between annotators (+-0 and +-1 document).
   Expected minimums: kappa >= 0.6, alpha >= 0.67; otherwise revise guidelines and re-annotate.
3. A third annotator adjudicates disagreements; record the adjudicated label with annotator_id `gold`.
4. Run `python convert_to_mllb.py annotations/ ../data/mllb_human_v1` and evaluate with
   `scripts/eval_mllb_synth.py --data data/mllb_human_v1 --split human`.
5. Freeze the set before any further change to the system; never tune on it.

## Appendix A: memory types
belief (what the author holds true/valuable), goal (desired future state), decision (a choice made),
preference (likes/dislikes), plan (concrete intended steps), reflection (looking back, lessons),
observation (noticed facts), knowledge (learned how something works), event (something that happened).
